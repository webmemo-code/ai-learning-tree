ai-learning-tree (github.com/webmemo-code/ai-learning-tree, PUBLIC now, MIT) visualizes Walter's AI learning journey as a growing 3D tree; anyone can hook up their GitHub + optional Obsidian. Origin brain dump: issue #1.

On 2026-07-13 a "wild and free" ideation session produced the phase-1 (Seed) docs. Since then the pipeline is BUILT and RUNNING: generator/ (deterministic grow() over an append-only growth-log → tree.json, taxonomy.mjs is the sector source-of-truth), harvester/ (nightly GitHub harvest, workflow_dispatch-runnable; classify() maps repo→sector via tree.config.yml), grove/ (multi-tree community layer), prototypes/mood-sketch (the renderer, reads ../../data/tree.json — MUST be served from the REPO ROOT: `python -m http.server 8123` then visit /prototypes/mood-sketch/, NOT from inside the sketch dir or `../` escapes the served tree).

Taxonomy is now **10 sectors in 4 limbs** (CREATE copy·images·video·**3d** / AUTOMATE workflows / DISTRIBUTE seo·geo / BUILD no-·low-·pro-code). create.3d added & wired through 2026-07-15 (PRs #16 sector+config+.gitattributes, #17 docs 9→10, #18 reclassify stale log rows). Vertical = Section AI's 4 levels (Novice/Experimenter/Practitioner/Expert) → forest strata (floor/understory/canopy/emergent).

**Contribution meadow** (2026-07-20, issue #34, PRs #35-38, ADR-0010): GitHub's calendar radialized onto the ground — weekly per-sector buckets in tree.json (`contribution` array, github-source only), rendered as glowing blades (height = week's commit count, rim-recent rings, sector hue, moonlit-desaturated by private share). KEY PRIVACY MODEL: Walter works 82% in private repos and WANTS that visible as aggregate intensity ({count, weight} only, never ids) — `privacy.contributions: combined` in his config, vault stays roots-only. Sector Walk camera: opposite-side azimuth, height DYNAMIC `12 + 3.5 × bounds.max[1]` (scales with growth). Ground click = sector select only (time scrubbing is the slider's job — Walter removed the ground scrubber after testing). entity-map remapped seo→geo (323 rows, GEO now Experimenter with own milestone).

**THE TIME-AXIS PIVOT (2026-07-31, PR #57 + successors) — supersedes several earlier decisions.** Walter revisited the "commits ride up with the tree" call and asked for a time-fixed look. Investigating it collapsed three assumptions at once:
1. **Terracing is dead.** The renderer's existing pagoda toggle (`?pagoda=1`) is the best case for tiered placement, and Walter's verdict was *"the visual difference is minimal, I can hardly spot it."* Discrete tiers can't carry the time axis.
2. **Milestones are being abandoned as the height gate.** Walter: *"they are less important than we initially thought because there is no hard threshold by which we can tell the new level was reached. Maybe we should let go of that idea."* Note **ADR-0004 was never Accepted — it sat at "Proposed — awaiting Walter's call"** for its whole life, so this is finally making the call, not reversing one. The evidence against it: all 5 milestones were authored in ONE week (2026-07-16→20, when the feature shipped) while the commits they certify span back to Dec 2024 — the dates record the tooling, not the skill. Rendering "level at commit time" literally would drop ~1600 commits to the Forest floor and read 19 months of real expertise as beginner work.
3. **Vertical becomes TIME, cut as QUARTERS.** Strata stop being competence bands. Years are too coarse (only 3, one with 4 events); quarters give 8 bands and preserve the transition below. Height = when, full stop — which dissolves the old "proficiency vs. chronology" tension because there's only one meaning left. Consequence to face: this largely un-does ADR-0008's acacia (the flat earned-ceiling top stops meaning anything). Walter's steer is *"go by the looks"* — a columnar growth-ring species, not a half-committed acacia.

**Maturity moved from height to TEXTURE.** Walter's insight: the commit/PR/review/issue MIX is a maturity signal ("novices don't work with those features"). It's behavioural — unfakeable by editing YAML — which is exactly what milestones failed to be. Harvester extended in PR #57; the backfill PROVED the hypothesis and it's a phase change, not a drift: reviews go **0 (2024) → 0 (2025) → 498 (2026)**; quarterly collaboration share jumps 10% → 55% in **2026Q2** and holds. **Ring thickness = commits-only, composition = the mix** (Walter's call) — because a PR's own commits are harvested too, so raw-event thickness would overstate 2026 ~3× as an artifact of workflow, not output.

**FORM SEARCH — WHERE IT STANDS (2026-07-31 evening, branch `feat/time-axis-concept-board`, NOT merged).** Walter's brief after seeing the first three 3D variants: *"They all have interesting aspects, but none is wow!"* Diagnosis: **the tree became a chart wearing bark** — all three place geometry at computed coordinates instead of growing it; nothing competes, dies back, or is irregular, so they read as diagrams. His two decisions when asked: **keep time VERTICAL** (don't explore radial/topological time) and optimise for **a LEGIBLE DATA OBJECT over a beautiful tree** — reading it always wins. He also liked the trunk-rings **side panels** (numbers table + legend), which need reducing on mobile; panels work, the FORM is what fails.

**THE RECONCILIATION RULE (the most valuable thing learned — obeys or fails):** tree-shape must come from **CUMULATIVE** quantities and data-reading from **PER-MONTH** quantities, on **different visual channels**. Every sketch driving shape from monthly volume inverted into a funnel (fat top, thin base) because Walter's mass genuinely sits at the recent end — the same inversion that sank trunk-rings. Only cumulative width keeps a tree-shaped base. Corollary: **uniform time-as-vertical is the problem, not time-as-vertical**; spacing months by mass fixes the empty canvas but over-corrects.

**Use MONTHLY buckets, not quarterly** — quarters gave 8 bands with half the canvas empty; months give 19, real texture, and surface detail quarters hid (e.g. the quiet 2026-03 dip that PRECEDES the 2026-04 collaboration jump). 2025-02 is a genuine missing month; 2025-05 has 1 commit. Never interpolate those away.

**Artifacts on the branch:** `prototypes/time-axis-board/` — three 3D variants (whorls/banded-ribs/trunk-rings, all "not wow"), `moodboard.html` (12 fast 2D form sketches, click-to-expand — strongest were **03 dieback/dead wood**, **05 da-Vinci downward thickness**, **10 espalier** as the legibility benchmark), and `radial-envelope.html`. **Documented dead ends:** width-from-monthly-volume (funnel, board-wide); per-month SHARE as primary geometric driver (one sector usually >50%, too little signal); point clouds (need ~10x this volume to read as emergent).

**Radial envelope — Walter's own reframe, half-succeeded, WAS MID-ITERATION WHEN WE STOPPED.** Per-sector azimuth loft: radius at (month, sector-bearing) = that sector's commits. Motivated by a real second maturity signal — per-month angular **asymmetry** falls 1.00 (2024-12, one sector all the mass) → 0.22 (2026-07, many sectors at once): a shift from serial to parallel work, structural rather than behavioural, independent of the kind-mix. **Result: the character change does NOT read in the solid** (roundness needs many sectors of comparable size, but 2026-07 is geo 155/pro-code 128/copy 54 — lopsided too, just bigger; solids of revolution read as vases). **It DOES read unmistakably in the CUT VIEW** — Sep '25 as one 71 lobe vs Jul '26 spread across six. **Walter's live reaction: "Now that's looking interesting! Can we give it some transparency and blooming?" — that is the NEXT TASK, not yet started.** Suggested follow-ups from the build: normalise each ring to its own max so shape (not magnitude) is what radius encodes; consider dropping the solid for a stack of 19 discrete rosette discs.

**Unencoded signals worth a channel:** sector SHAPES differ more than totals (`automate.workflows` 495 commits over 14 months = sustained; `distribute.geo` 397 over 6 = bursty). The sector×month grid is only **29% filled** (56/190) — any design wanting a full canopy invents filler. And `distribute.seo` holds a level-2 milestone on **16 commits**, so anything sized by commits renders a real competence as nothing — an argument for keeping milestones as MARKERS even after dropping them as a height gate.

**Gotchas:** (0) **PER-FAMILY CURSORS (PR #57) — the log is the cursor, and it now has three.** `indexExisting` tracks a high-water mark per `{commit, pr, issue}`. A single shared cursor is a *silent data-loss bug*: a June PR pushes the commit floor past unharvested Feb commits, which are then lost forever while the harvester cheerfully reports "no new growth". Reviews deliberately fold into the `pr` family (fetched per-PR, no list endpoint of their own, so they must never SET a cursor). Related: the per-PR review fetch gates on `updated_at`, NOT `created_at` — a Feb PR reviewed in July would otherwise be missed permanently. Also: persistent 5xx soft-fails on collaboration endpoints but MUST still abort on commits, for the same cursor reason. (1) tree.config.yml has a fragile hand-rolled YAML parser (serialize.mjs) — a comment after a value breaks on CRLF; `.gitattributes` now forces LF, keep it. Walter's git is core.autocrlf=true so fresh checkouts smudge to CRLF on disk — tests/build need LF. (2) Harvester is append-only keyed by commit id: re-mapping a repo does NOT re-classify already-logged rows; they keep their frozen sector until new commits land (or a manual reclassify — see PR #18's one-off approach: reuse classify()+jline() from harvest.mjs verbatim so unchanged rows stay byte-identical). **Corollary — always re-check the log at MERGE time, not just when opening the PR:** a nightly harvest can land between the two and freeze fresh `unclassified` rows for the very repo being mapped. That happened in PR #54 (6 flickr-lightroom-publisher rows) and needed follow-up PR #55, which also swept up 25 long-stale content-writing rows. When adding ANY repo mapping, grep `data/growth-log.jsonl` for `"sector": "unclassified"` before declaring the job done — the whole-file audit is as cheap as the single-repo one and catches older misses.
