The ruleset — where the weights come from

weight(sector) = share of that repo's GitHub topics mapping to it. Systematic, auditable, and an extension of the topic-map already in tree.config.yml — not a parallel mechanism. Topics captured 2026-08-01 and baked in; no API call at runtime.

Worked example — flickr-to-instagram-automation, 16 topics: 3 image (flickr-photos, gpt-4-vision, vision-api), 9 workflow, 4 agent → .19 / .56 / .25. That single repo moves 208 commits off a pure workflow reading.
